## 1. 무엇이 바뀌었나 (쉬운 설명)

센서값이 정상 범위를 벗어나면 **사람이 주입 버튼을 누르지 않아도** 메인 앱에 이벤트와 이력이 자동으로 생깁니다.
주입 탭의 "센서 경로 주입"은 이 센서값을 일부러 흔드는 테스트 버튼입니다.

```
센서값 (/lab/plant 와 같은 값)
  → 정상 범위 비교 (sensorMonitor)
  → 변화율(delta) 계산
  → 기존 Rule Engine (runRuleEngine) 으로 판정   ← 판정은 여기서만
  → 이벤트 · 이력 · 지도 상태
  → Advisor 는 설명만
```

"규칙 엔진 변경"은 이 중 `runRuleEngine` 에 **규칙 2개를 추가**한 것입니다. 기존 규칙은 하나도 고치지 않았습니다.

| 추가한 규칙 | 조건 | 결과 | 왜 필요한가 |
|---|---|---|---|
| 냉각라인 단독 온도 상승 | 온도만 오르고 진동·전류는 그대로 | 냉각라인 0.60 (주의) | 냉각수 문제는 로봇 진동과 무관하게 온도만 올리기 때문 |
| 전원 공급 중단 | 전류와 진동이 모두 -80% 이하 | 전원 공급 중단 0.75 (이상) | 전원이 끊기면 값이 오르는 게 아니라 0 으로 떨어지기 때문 |

판정 기준값(0.5 주의 / 0.7 이상)은 그대로입니다. 새 규칙은 점수만 내고, 임계값은 바꾸지 않았습니다.

## 2. 기존 동작이 그대로인 근거

- 주입 시나리오 6종 × 강도 3단계의 Rule Engine 출력(점수, 후보, 근거, 권장 조치, 상태)을 규칙 추가 전후로 저장해 비교했습니다. **전부 동일**합니다.
  대표값: 베어링 마모(중) → 베어링 마모 0.78, 냉각라인 0.20, 상태 이상. 변하지 않았습니다.
- 새 규칙은 주입 경로에서는 만들어질 수 없는 패턴(온도 단독 상승, 전류·진동 동시 소실)에서만 점수가 올라갑니다.
- 센서 경로 결과가 `/lab/plant`의 설비 상태와 같은지 로봇 3대 × 40개 시점으로 비교했습니다(정상·베어링 마모·모터 과부하·냉각수 유량 저하·차단기 트립).

### 규칙과 부딪히는 점 (판단 필요)

- **"이력 행은 주입 탭에서만 생김"** 과 달라집니다. 센서 경보도 이력 행을 만듭니다(시나리오 `sensor`, 강도 `자동`, "센서 자동 감지" 표시와 감지 근거 포함). 의도된 변경이지만 이 체크리스트 문구를 고칠지는 공장 판단이 필요합니다.
- **같은 로봇에 수동 주입이 있으면 센서 모니터는 건드리지 않습니다.** 수동이 항상 우선합니다.
- 센서 경보는 값이 정상으로 돌아오면 **자동 복구**되고, 복구되면 지도에서 ! 가 사라집니다(이력은 "해결됨"으로 남음).
- **"원인 미상" 표시(센서 경보에만 적용)**: 센서는 벗어났는데 엔진의 1위 후보가 기준 0.5 미만이면(예: 로봇 03의 보호가스 압력 이탈 → 베어링 마모 0.30) 이벤트·이력·카드에 "원인 미상"으로 표시하고, 권장 조치와 Advisor 설명 버튼은 막습니다. 수동 주입은 엔진 출력이 그대로이고 이 표시를 쓰지 않습니다. 엔진 자체는 바꾸지 않았습니다.
- 지도 상태: 로봇은 엔진 판정과 플랜트 상태 중 더 나쁜 쪽으로 표시합니다(엔진이 원인을 못 찾아도 센서가 벗어난 로봇을 정상으로 보이지 않게 함). 상단 칩도 같은 규칙입니다.

## 4. 아직 확인하지 않은 것

- 레포 자체의 `npm run build` (`--turbopack`). 제 검증은 복사본 webpack 빌드와 `tsc`, `eslint` 까지입니다.
- 센서 경보 상태에서 Advisor 설명 생성(원인 미상이 아닌 경우, 예: 칠러 냉각 손실의 냉각라인 0.60). 설명 버튼 자체는 열려 있지만 실행해 보지 않았습니다.
- 로봇이 아닌 설비(프레스·세척기 등)는 센서 경보로 이벤트·이력이 생기지 않습니다(엔진이 로봇 3대 기준). 지도와 칩에는 반영됩니다.
- 센서값, 정상 범위, 시나리오는 모두 **가정**입니다(근거 수준: assumed). 실제 설비 데이터가 아닙니다.
